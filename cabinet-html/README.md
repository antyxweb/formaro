# Formaro — Кабинет партнёра (прототип)

Прототип административного раздела `/cabinet/` для партнёров маркетплейса
спецодежды **Formaro**. Технологии: **HTML + jQuery + AJAX** (без бэкенда).

## Как открыть

Браузеры блокируют AJAX-запросы к локальным файлам (`file://…`), поэтому
папку нужно открыть через локальный сервер, а не двойным кликом по файлу:

```bash
cd cabinet
python3 -m http.server 8000
# или: php -S localhost:8000
# или: npx serve
```

Затем открыть `http://localhost:8000/login.html` (логин/пароль не
проверяются — это прототип) или сразу `http://localhost:8000/index.html`.

## Как это устроено

- **Данные** лежат в `data/*.json` и один раз загружаются через AJAX
  (`$.getJSON`). Дальше все изменения (добавление/редактирование/удаление
  категорий, товаров, заказов и т.д.) пишутся в `localStorage` —
  так формы «Сохранить/Применить/Удалить» по-настоящему работают и
  переживают переход между страницами, хотя бэкенда нет (см. `dsLoad`/
  `dsSave` в `assets/js/common.js`). Чтобы сбросить все изменения к
  исходным демо-данным — очистите localStorage сайта в devtools.
- **Партиалы**: сайдбар, шапка и футер лежат в `partials/*.html` и
  подгружаются в каждую страницу через `$('#...').load(...)` (тоже AJAX).
  Меняете один файл — обновляется во всех разделах сразу.
- **Тема**: светлая/тёмная, авто (по системе) или ручной выбор —
  переключатель в шапке, сохраняется в `localStorage`. Применяется
  инлайн-скриптом в `<head>` каждой страницы до отрисовки, чтобы не было
  мигания при загрузке.
- **Изображения**: без сервера загрузка реализована через
  `FileReader`/`data:` URL — выбранная картинка сразу превращается в
  превью и сохраняется как base64-строка в localStorage.

## Разделы

| Раздел | Файлы |
|---|---|
| Главная (дашборд: заказы/сумма/топ товаров, фильтр по датам и статусу) | `index.html`, `assets/js/dashboard.js` |
| Категории (дерево, чекбоксы, поиск, массовое удаление) | `categories.html` → `category-detail.html` |
| Товары (свойства + произвольные атрибуты + галерея) | `products.html` → `product-detail.html` |
| Заказы (список + фильтры + деталка с составом и покупателем) | `orders.html` → `order-detail.html` |
| Новости | `news.html` → `news-detail.html` |
| Данные партнёра (верификация, реквизиты, смена пароля) | `partner.html` |
| Финансы (баланс, история, вывод средств, запрос документов) | `finance.html` |
| Уведомления | `notifications.html` |
| Чат с клиентами (фильтр по клиенту/заказу/товару/дате) | `chat-clients.html` |
| Техподдержка (тикеты, вложения, контакты и реквизиты площадки) | `support.html` |
| Вход (по e-mail, без регистрации) | `login.html` |
| Правовая информация (соглашение, политика, оферта, реквизиты) | `legal.html` |
| Предпросмотр товара/категории/новости («переход на сайт») | `preview.html` |

На страницах категории/товара/новости — четыре кнопки: **Предпросмотр**
(открывает `preview.html` в новой вкладке — имитация публичной страницы
сайта), **Сохранить** (сохраняет и возвращает в список), **Применить**
(сохраняет и остаётся на странице) и **Отмена**.

## Что дальше (для перехода от прототипа к реальному продукту)

1. Заменить `data/*.json` + `localStorage` на реальный бэкенд (API),
   сохранив структуру данных — вся логика уже рассчитана на асинхронные
   AJAX-вызовы, поменять нужно будет только реализацию `dsLoad`/`dsSave`.
   Ранее уже готовился вариант на PHP + JSON-файлах — можно взять его как
   основу для API.
2. Добавить реальную аутентификацию и разграничение доступа партнёров.
3. Заменить загрузку картинок через `data:` URL на реальную загрузку
   файлов на сервер.

## Подключённые сторонние jQuery-плагины

- **Trumbowyg** (`category-detail`, `product-detail`, `news-detail`, `partner`) —
  WYSIWYG-редактор для полей "Подробное описание". Тема оформлена под сайт
  в `assets/css/theme.css` (блок "Rich text"). Точка входа — функция
  `initRichText(sel)` в `common.js`: при сохранении форма читает HTML через
  `$(sel).trumbowyg('html')`.
- **jquery-datetimepicker** (`news-detail`) — объединённое поле "Дата и
  время" вместо двух раздельных полей. Тема — блок "Datetimepicker" в
  `theme.css`.

Обе библиотеки подключены с CDN (jsdelivr) — при переносе в закрытый контур
(например, в модуль 1С-Битрикс, см. ниже) их нужно будет разместить локально.

## Важно: планируется перенос в модуль 1С-Битрикс

Прототип изначально делается с прицелом на последующий перенос в модуль
**1С-Битрикс: Управление сайтом**. Это уже отражено в структуре кода —
при переносе стоит обратить внимание на следующее:

- **Слой данных изолирован**: весь доступ к данным идёт только через
  `dsLoad(entity, path)` / `dsSave(entity, data)` в `common.js`. При переносе
  в Битрикс эти две функции переписываются на вызовы компонентов/агентов
  (например, `BX.ajax.runComponentAction`) — остальной код (все `*.js` на
  страницах) менять не придётся, он ничего не знает про localStorage.
- **Партиалы сайдбара/шапки/футера** (`partials/*.html`) — в Битриксе это
  естественно ложится на `header.php`/`footer.php` компонента или на
  собственные подключаемые шаблоны (`include`), сама разметка уже вынесена
  отдельно и не продублирована по страницам.
- **jQuery уже является зависимостью Битрикса** (ядро `jquery` core), так
  что весь код на чистом jQuery без сборщиков — переносится "как есть".
  Trumbowyg и jquery-datetimepicker тоже чистые jQuery-плагины без сборки.
- **Загрузка файлов через `data:` URL** — временное решение для прототипа
  без бэкенда; в модуле Битрикса заменяется на `CFile::SaveFile` через
  AJAX-обработчик, сигнатура остаётся той же (файл → URL).
- **Дерево категорий** реализовано как обычный список с `parent_id` —
  ложится на инфоблоки с иерархическими разделами почти без изменений
  логики (`categoryDirectChildren`/`categoryRoots`/`categoryDescendantIds`
  в `common.js` достаточно будет запитать от реального дерева разделов
  инфоблока).
- **Множественная привязка товара к категориям** (`product.category_ids`)
  соответствует множественной привязке элемента инфоблока к разделам в
  Битриксе (поле `IBLOCK_SECTION`, `ADDITIONAL_PROPERTY_CODE`) — переносится
  без изменения UI (`renderCategoryCheckboxTree`).

Если решите переносить — дайте знать, распишу пообъектно, что в какой
компонент/инфоблок/агент ложится.
