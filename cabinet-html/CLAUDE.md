# CLAUDE.md — памятка для агента

Это заметки **для Claude/AI-агента**, а не для человека (для человека — `README.md`).
Формат: почему всё устроено именно так, и на какие грабли уже наступали, чтобы
не наступать повторно.

## Что это

Чистый клиентский прототип (без сборщика, без бэкенда) кабинета партнёра
маркетплейса Formaro. HTML + jQuery 3.7 + Bootstrap 5.3 (переопределён кастомной
темой) + `localStorage` как псевдо-БД. Запуск: `python3 -m http.server 8000` из
папки `cabinet/` (не открывать файлы напрямую — AJAX к `data/*.json` не сработает
через `file://`).

## Данные и сохранение — ОБЯЗАТЕЛЬНО прочитать перед правкой JSON-схем

- Источник правды при первой загрузке — `data/*.json`. Дальше всё читается/пишется
  через `dsLoad(entity, path)` / `dsSave(entity, data)` в `assets/js/common.js`,
  версионируется через `CABINET_DATA_VERSION` (наверху `common.js`).
- **При любом изменении структуры существующего JSON-файла (новое поле, новый
  формат) — увеличивай `CABINET_DATA_VERSION` на 1.** Иначе у пользователя,
  который уже открывал прототип, в localStorage останется старый кэш без нового
  поля, и фича не заработает, пока он вручную не очистит localStorage.
- `discounts.json` — единственный файл, где ОДИН объект хранит сразу две
  сущности: `{discounts: [...], coupons: [...]}`. При сохранении одной из них
  не забывай подтягивать актуальный файл целиком и не терять вторую половину
  (см. `saveDiscountsData()` в `discounts.js` как образец).

## Мультитенантность (partner_id)

- Есть константа `CURRENT_PARTNER_ID` в `common.js` (сейчас захардкожена как `1` —
  в прототипе без бэкенда нет настоящей авторизации разных партнёров).
- Категории: 201 «системная» категория (`is_system: true`, общие для всех,
  нельзя редактировать/удалять никому) + партнёрские (`partner_id`, видны только
  владельцу). Хелперы: `isSystemCategory`, `isCategoryVisible`, `visibleCategories()`,
  `canEditCategory()`.
- Товары/новости/скидки/купоны: просто `partner_id`, хелпер `ownOnly(rows)`.
- **Паттерн безопасного сохранения** (важно!): т.к. в память подгружаются
  ТОЛЬКО свои/видимые записи, при `dsSave` нельзя просто записать
  отфильтрованный массив — так потеряются чужие партнёрские записи, которые
  не грузились. Правильно: подтянуть заново ПОЛНЫЙ файл, отфильтровать из
  него чужие, склеить с обновлёнными своими. Готовые хелперы:
  `saveVisibleCategories()` (категории), `saveOwnRows(entity, path, ownRows, cb)`
  (товары/новости), `saveDiscountsData()` в `discounts.js` (скидки/купоны).

## Иконки: только Lucide, инлайн-SVG — НЕ Bootstrap Icons

Изначально использовались `<i class="bi bi-*">` (Bootstrap Icons), но по ходу
разработки **весь проект переведён на инлайн-SVG иконки Lucide**
(`stroke="currentColor"`, класс `ic-inline` для размера/выравнивания).
Bootstrap Icons (`bootstrap-icons.css`) всё ещё подключены в `<head>` каждой
страницы «на всякий случай», но новые иконки добавляй только как Lucide SVG.

- Где взять path конкретной иконки: не выдумывай из памяти без крайней
  необходимости — попроси у пользователя reference-файл (HTML-экспорт со
  страницей, где нужная иконка уже есть) и вытащи `<path>` оттуда. Так делалось
  весь проект — пользователь присылал скриншоты/HTML с нужным набором иконок.
- Готовые повторно используемые SVG уже «размётаны» по проекту как строковые
  константы в разных `*.js` (например `GSEARCH_ICONS` в `common.js`,
  `NOTIF_TYPES` в `notifications.js`) — прежде чем тащить новый path откуда-то,
  проверь, нет ли уже нужной иконки в другом файле (grep по характерному
  фрагменту `<path d=`).
- Сайдбар/шапка/дашборд/списки/попапы/чат/техподдержка/уведомления/финансы —
  везде Lucide. Если увидишь `bi-*` в новом месте — это, скорее всего,
  недосмотр, стоит заменить на Lucide для консистентности.

## Скрытые ловушки CSS (уже отловленные баги — не наступай снова)

1. **`* , *::before, *::after { border-radius: 0 !important; }`** в
   `theme.css` — весь интерфейс намеренно плоский (было отдельное ТЗ «убери все
   скругления»). Если где-то нужен скруглённый элемент (пилюли статусов,
   переключатели, аватар, счётчики, скошенный угол логотипа/плиток) — точечно
   перебивай `border-radius: N !important;` на самом элементе. НЕ убирай
   общее правило целиком.
2. **`.table-responsive` даёт `overflow-x:auto`**, из-за чего браузер неявно
   выставляет и `overflow-y:auto` — это ломает `position:sticky` у футера
   таблицы. Исправлено `.table-responsive { overflow-y: visible; }` — не
   убирай это правило.
3. **`<tfoot>` красит верхнюю границу в `currentColor`** (Bootstrap-дефолт) —
   без явного `border-top-color` в тёмной теме получается белая полоса.
   Исправлено правилом `.table > tfoot { border-top-color: var(--border-strong); }`.
4. **`.cbtree`** (класс дерева категорий с чекбоксами, `renderCategoryCheckboxTree`
   / `renderCategoryRadioTree`) даёт `max-height + overflow-y:auto` контейнеру.
   Если тот же DOM-контейнер потом используется для ДРУГОГО виджета (например,
   поиск+чипы товаров в скидках), нужно явно `.removeClass('cbtree')` —
   иначе контент обрежется по высоте.
5. **Подсказки валидации** (`initFormValidation` в `common.js`) вставляются
   через `$el.after($hint)`. Если поле лежит внутри `.input-group`
   (например, «Код» с кнопкой-цепочкой рядом) — подсказка ломает flex-раскладку
   группы. Функция уже это учитывает (`$el.closest('.input-group')`), но если
   добавляешь НОВОЕ поле в `.input-group` с `data-validate` — проверь, что
   подсказка не влезла внутрь группы визуально.
6. **`.btn` — flex-контейнер с `min-height`** (`display:inline-flex;
   align-items:center; justify-content:center; gap:.4rem; min-height:38px;`).
   Если нужна МЕЛКАЯ кнопка внутри узкого места (например, крестик на
   превью галереи, 24×24px) — обязательно сбрасывай `min-height: 0` в
   точечном правиле, иначе `min-height:38px` раздует кнопку.
7. **`a:hover { text-decoration: underline; }`** — общее правило для всех
   ссылок. Любая ссылка, оформленная как кнопка/карточка (`.btn`,
   `.discount-item`, `.variant-item .variant-name a`), должна быть в
   списке исключений рядом с этим правилом — иначе будет подчёркиваться
   при наведении.
8. **Дата без времени** (`"2026-08-01"`) через `new Date(iso)` +
   `toLocaleTimeString` даёт сдвиг часового пояса (UTC-полночь → 03:00 по
   Москве). Для чисто-датовых полей используй `fmtDateShort(iso)` из
   `common.js` (парсит как `iso + 'T00:00:00'`, без сдвига), а не `fmtDate()`.

## Общие переиспользуемые компоненты (common.js)

- `initTablePager(opts)` — пагинация + переключатель количества строк + счётчик,
  работает и на `<table>` (ищет `.tf-pagesize-select`/`.tf-pager`/`.tf-count`
  внутри `opts.root`), и на обычном `<div>`-списке (уведомления, чат) — не
  обязательно таблица.
- `bindClearFilters(clearBtnSel, watchSel, resetFn)` — кнопка сброса фильтров,
  видна только если что-то реально изменено. **Важно**: если поле фильтра
  заполняется программно ДО вызова `bindClearFilters` (например, `category_id`
  из URL применяется раньше), эта программная подстановка ошибочно станет
  «дефолтом». Вызывай `bindClearFilters` максимально РАНО в скрипте, до любых
  программных предзаполнений полей.
- `bindCodeChain(nameSel, codeSel, chainBtnSel)` — связка «название → код» с
  иконкой-цепочкой (как в 1С-Битрикс): пока цепочка включена — код авто-
  генерируется; ручной ввод в код или клик по иконке — размыкает. У уже
  сохранённой записи цепочка должна быть сразу разомкнута (`.setExisting()`).
- `renderCategoryCheckboxTree` (множественный выбор, с каскадом на потомков) /
  `renderCategoryRadioTree` (одиночный выбор, для «родительский раздел») — оба
  с полем поиска сверху, при поиске схлопываются в плоский список с указанием
  полного пути.
- `initFormValidation()` — авто-подключается на каждой странице через
  `$(function(){ initFormValidation(); })` внутри `common.js`. Просто повесь
  `data-validate="text|phone|email|password|slug"` на инпут — подсказка/
  подсветка/маска телефона подключатся сами. Для «повторите пароль» —
  `data-validate-match="#selector_first_password_field"`.
- `showConfirm(msg, onConfirm, opts)` / `showResult(ok, msg)` — кастомные
  модалки вместо `confirm()`/`alert()`. **У КАЖДОЙ страницы, где вызывается
  `showConfirm`, в разметке должна быть модалка `#confirmModal`** (шаблон в
  любом `*-detail.html`) — иначе тихий фолбэк на нативный `confirm()`
  (это уже случалось на нескольких detail-страницах, где скопировали JS,
  но забыли скопировать HTML модалки).

## Структура страниц

Списки: `categories/products/orders/news/discounts/support`.html + одноимённый
`assets/js/*.js`. Детальные: `*-detail.html` + `*-detail.js`, паттерн кнопок
внизу — **Сохранить / Применить / Отмена / Удалить** слева (именно в этом
порядке), **Предпросмотр** справа (через `flex-spacer`). У сущностей с
публичной витриной (категория/товар/новость) «Предпросмотр» ведёт на
`preview.html?type=X&id=Y`, `href` обновляется динамически после первого
сохранения новой записи.

Раздел «Скидки и купоны» (`discounts.html`, вкладки) — самый свежий и самый
полный пример паттернов проекта: две сущности в одном файле данных, авто-
подбор скидки в заказе по условиям (`order-detail.js` → `autoApplyBestDiscount`),
пикер целей скидки (категории/товары) с переключением UI по типу.

## Чего в проекте официально НЕТ (не пытайся чинить как баг)

- Настоящей аутентификации/сессий — `CURRENT_PARTNER_ID` захардкожен.
- Реальной загрузки файлов на сервер — картинки хранятся как `data:` base64
  прямо в localStorage (см. `README.md`, раздел про перенос на бэкенд).
- Хранения СОДЕРЖИМОГО файлов у документов партнёра (`partner.html`,
  вкладка «Документы») — только метаданные (имя/размер/дата), т.к. localStorage
  физически не тянет файлы до заявленных 20 МБ.
